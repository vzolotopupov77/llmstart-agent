## Цель спринта

Инструментировать агента мониторингом контекста и через verbose-режим наглядно показать, как токены накапливаются шаг за шагом — чтобы пользователь увидел проблему своими глазами до того, как увидит решение.

**Боль, которую закрывает:** после Sprint 02 агент работает, но «под капотом» непрозрачно. Пользователь не видит, как растёт контекст при проверке большого репо. Этот спринт делает невидимое видимым.

**Deep-agent механизм:** мониторинг контекста — стриминг событий deepagents с подсчётом токенов на каждом шаге. Образовательная цель: зафиксировать боль раздувания *до* введения субагентов.

## 🎭 Образовательная драматургия

Это первый из двух «образовательных» спринтов. Задача — не решить проблему, а **сделать проблему видимой**.

Пользователь запускает `--verbose` на объёмном репо (30+ файлов) и видит:
- контекст растёт с каждым шагом: +8K, +5K, +4K...
- к синтезу накоплено 20–25K токенов
- финальный экран фиксирует: «всё это — в одном контексте → Sprint 04 покажет решение»

После этого спринта у пользователя есть интуитивное понимание *зачем* нужна изоляция. Sprint 04 станет не просто «добавили субагентов», а ответом на реально прожитую боль.

## Задача 01: context-tracker 📋

### Цель

Перехватить event stream deepagents и извлекать из него размер контекста (токены) после каждого шага агента; эмитировать структурированные `ContextEvent` для рендерера.

> 💡 **Скиллы:** `deep-agents-core/SKILL.md` — формат events при стриминге; `langchain-fundamentals/SKILL.md` — `usage_metadata` в ответах модели.

### Состав работ

- [ ] Реализовать `mentor/events.py`: dataclass `ContextEvent(step: str, tokens_before: int, tokens_after: int, files_read: list[str])`
- [ ] Реализовать `mentor/tracker.py`: функция `stream_with_tracking(...)` — парсинг `messages` из `stream(updates)` (callbacks в LangGraph не доходят до LLM)
- [ ] Маппить шаги агента к именам из плана (todo): при обновлении todo-статуса эмитировать `PlanEvent(step, status)`
- [ ] Добавить `tokens_before` / `tokens_after` к каждому `ContextEvent`: сохранять предыдущее значение между вызовами
- [ ] Самопроверка: `make lint && make typecheck`

### Критерии готовности (DoD)

**Агент проверяет:**

| # | Критерий | Способ проверки |
|---|----------|-----------------|
| 1 | `ContextEvent` содержит корректные поля `tokens_before`, `tokens_after`, `files_read` | unit-тест с mock event stream |
| 2 | Дельта токенов считается правильно | unit-тест |
| 3 | Линтер и типы чистые | `make ci` |

**Пользователь проверяет:**

- В debug-логах (`LOG_LEVEL=DEBUG`) видны сырые события и извлечённые значения токенов

### Артефакты

- `mentor/events.py`
- `mentor/tracker.py`
- `tests/test_tracker.py`

## Задача 02: verbose-renderer 📋

### Цель

Реализовать Rich verbose-рендеринг: живое обновление плана с todo-статусами, события файловой системы, рост контекста после каждого шага, итоговая панель «анализ контекста».

> 💡 **Скиллы:** `deep-agents-core/SKILL.md` — паттерн стриминга событий в CLI; образовательная цель спринта — показать *проблему*, не решение.

### Состав работ

- [ ] Реализовать `mentor/renderer.py`: класс `VerboseRenderer` с методами `on_plan_update`, `on_context_event`, `on_file_event`, `on_complete`
- [ ] `on_plan_update` — перерисовать панель плана с обновлёнными статусами (Rich `Live`)
- [ ] `on_file_event` — вывести строку `  📄 Прочитан: <путь>` под текущим шагом; если путь не начинается с `code/` и не является служебным (`submission.md`, `rubric.md`, `code-index.md`, `plan.md`, `notes/`, `briefs/`) — добавить предупреждение `  ⚠ Путь вне code/: <путь>`
- [ ] `on_context_event` — вывести строку роста контекста: `  Контекст: {before} → {after} токенов (+{delta})`; выделить красным, если `after > 0.5 * context_limit`
- [ ] `on_complete` — итоговая панель «Контекст за сессию»: таблица шагов с дельтами, суммарный итог, доля от лимита; предупреждение если > 30%
- [ ] Интегрировать `VerboseRenderer` в `mentor/cli.py`: при флаге `--verbose` оборачивать `stream_with_tracking` вызовом рендерера
- [ ] Compact-режим не трогать (существующий рендерер остаётся)
- [ ] Самопроверка: `make lint && make typecheck`

### Критерии готовности (DoD)

**Агент проверяет:**

| # | Критерий | Способ проверки |
|---|----------|-----------------|
| 1 | `--verbose` и `--compact` дают разный вывод | запустить оба режима, сравнить |
| 2 | Plan-панель обновляется в реальном времени | наблюдать ✓/○ статусы в терминале |
| 3 | Контекст-строки появляются после каждого шага | проверить вывод |
| 4 | Итоговая панель контекста отображается после Feedback | прочитать финальный вывод |
| 5 | `make ci` → exit 0 | `make ci` |

**Пользователь проверяет:**

- Картина роста контекста читается без дополнительных объяснений
- Финальное предупреждение «весь код — в одном контексте» понятно и создаёт запрос на решение

### Артефакты

- `mentor/renderer.py`
- `mentor/events.py` (дополнен при необходимости)
- `mentor/cli.py` (интегрирован `VerboseRenderer`)
