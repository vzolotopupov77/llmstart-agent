## Цель спринта

Добавить явные механики управления контекстом оркестратора: вынос в файлы, суммаризация истории, компактизация — и сделать каждое срабатывание видимым через Rich-панель с токенами до/после.

**Боль, которую закрывает:** после Sprint 04 субагенты изолированы, но оркестратор сам накапливает историю переписки между шагами. К синтезу у него 15–20K токенов собственной истории. На больших репо или при многих аспектах рубрики это снова становится проблемой.

**Deep-agent механизм:** context engineering — три механики deepagents:
1. **Вынос в файлы** — объёмные данные уходят в `workspace/`, в окне — только ссылка и саммари
2. **Суммаризация истории** — при достижении `summarization_threshold` deepagents сжимает старые сообщения в резюме
3. **Компактизация** — при превышении `context_limit` весь контекст сворачивается до минимума: текущий `plan.md` + ключевые ссылки

## Задача 01: ce-mechanisms 📋

### Цель

Настроить deepagents summarization и compaction; оформить явный вынос объёмных данных в `workspace/` через CE-aware инструмент; убедиться, что агент после CE-событий продолжает работу корректно.

> 💡 **Скиллы:** `deep-agents-core/SKILL.md` — параметры `summarization_threshold` и `context_limit` в `create_deep_agent`; `deep-agents-memory/SKILL.md` — паттерн «write-then-reference».

### Состав работ

- [ ] Поля `summarization_threshold` и `context_limit` уже в `mentor/config/__init__.py` и `config.yaml` (абсолютные токены)
- [ ] Настроить `SummarizationMiddleware` через `middleware=[...]` + `register_harness_profile(excluded_middleware={"SummarizationMiddleware"})` — дефолт deepagents не принимает эти kwargs напрямую
- [ ] `trigger=("tokens", config.summarization_threshold)`, `keep=("fraction", 0.1)`; `context_limit` — для панелей и детекции compaction при overflow
- [ ] Реализовать CE-aware tool `write_to_workspace(content, filename, summary)` — записывает `content` в `workspace/<filename>`, возвращает агенту только `summary` + путь; в event stream эмитирует `FileOffloadEvent`
- [ ] Обновить system prompt оркестратора: инструктировать использовать `write_to_workspace` для объёмных данных (сырой код, длинные списки, полные ноты субагентов)
- [ ] Добавить `FileOffloadEvent`, `SummarizationEvent`, `CompactionEvent` в `mentor/events.py`
- [ ] Обновить `mentor/tracker.py`: перехватывать события суммаризации и компактизации из deepagents stream
- [ ] Написать тест: при mock-событии суммаризации tracker эмитирует `SummarizationEvent` с корректными полями
- [ ] Самопроверка: `make lint && make typecheck && make test`

### Критерии готовности (DoD)

**Агент проверяет:**

| # | Критерий | Способ проверки |
|---|----------|-----------------|
| 1 | `SummarizationEvent` содержит `tokens_before`, `tokens_after` | unit-тест с mock |
| 2 | `write_to_workspace` записывает файл и возвращает только summary | интеграционный тест |
| 3 | При низком `summarization_threshold` суммаризация срабатывает в ходе прогона | запустить с `summarization_threshold: 0.3` |
| 4 | Линтер и типы чистые | `make ci` |

**Пользователь проверяет:**

- После суммаризации агент не «забывает» текущий план и не начинает заново
- Файлы в `workspace/` содержат полные данные; в истории агента — только саммари

### Артефакты

## Задача 02: verbose-ce-panels 📋

### Цель

Расширить `VerboseRenderer` тремя типами CE-панелей: вынос в файлы, суммаризация, компактизация — каждая показывает механизм, токены до/после, сэкономлено.

> 💡 Цель не техническая, а образовательная: пользователь должен увидеть название механизма, конкретные числа и понять, что именно произошло с его контекстом.

### Состав работ

- [ ] Добавить в `VerboseRenderer` метод `on_file_offload(event: FileOffloadEvent)`:
  ```
  ╭─ Context Engineering: Вынос в файлы ─────────────────────────────╮
  │  Файл:    workspace/<filename>                                    │
  │  До:      X токенов в окне                                        │
  │  После:   Y токенов (ссылка + саммари)                            │
  │  Экономия: Z токенов                                              │
  ╰───────────────────────────────────────────────────────────────────╯
  ```
- [ ] Добавить в `VerboseRenderer` метод `on_summarization(event: SummarizationEvent)`:
  ```
  ╭─ Context Engineering: Суммаризация истории ───────────────────────╮
  │  Триггер:  окно достигло X% от context_limit                      │
  │  До:       A токенов                                               │
  │  После:    B токенов (summary сохранён в контексте)               │
  │  Экономия: C токенов                                              │
  ╰───────────────────────────────────────────────────────────────────╯
  ```
- [ ] Добавить в `VerboseRenderer` метод `on_compaction(event: CompactionEvent)`:
  ```
  ╭─ Context Engineering: Компактизация ──────────────────────────────╮
  │  Триггер:  контекст превысил context_limit                        │
  │  До:       A токенов                                               │
  │  После:    B токенов (plan.md + ключевые ссылки)                  │
  │  Экономия: C токенов                                              │
  ╰───────────────────────────────────────────────────────────────────╯
  ```
- [ ] Обновить итоговую панель «Контекст за сессию»: добавить секцию «CE-события» — тип, количество срабатываний, суммарная экономия
- [ ] Обновить `mentor/cli.py`: маршрутизировать новые события к соответствующим методам рендерера
- [ ] Самопроверка: `make lint && make typecheck`
