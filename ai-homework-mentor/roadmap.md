# Roadmap — AI Homework Mentor

> **Vision:** [concept/vision.md](concept/vision.md)
> **Последнее обновление:** 2026-07-24 (Sprint 07 закрыт, v1.0)

---

## Цель продукта

Внутренний агент-ревьюер для проверки домашних заданий студентов: принимает код (GitHub-ссылка или локальная директория), проверяет его через изолированных субагентов по рубрике и возвращает actionable фидбэк — наглядно показывая в работе механики фреймворка `deepagents`.

## Слои продукта

Каждый слой строится по принципу **цепочки вынужденных решений**: предыдущий слой работает, но вскрывает новую боль — следующий слой её закрывает. Каждый слой добавляет один характерный deep-agent механизм и оставляет рабочую утилиту.

### v0.1 — Фундамент: E2E-сценарий в одном агенте ✅

**Механизм слоя:** планирование (todo) + файловая система как рабочая память

**Цель:** закрыть сквозной сценарий проверки от входа до фидбэка. Агент строит явный план, читает код, проверяет последовательно по аспектам рубрики (без субагентов), пишет все артефакты в `workspace/`, возвращает структурированный фидбэк.

**Ключевые результаты:**
- [x] Принять вход: GitHub-ссылка или локальный путь + описание задания
- [x] Получить код: `git clone` или чтение директории в `workspace/code/`
- [x] Построить наблюдаемый план (todo) и вести его статусы
- [x] Проверить код по дефолтной рубрике, записать артефакты в `workspace/`
- [x] Вернуть Feedback через Rich CLI (compact-режим)
- [x] Конфигурация: `config/config.yaml` + `.env` (OpenRouter, модель)

**Спринты:**
| # | Sprint | Цель | Статус | Документ |
|---|--------|------|--------|---------|
| 01 | foundation | Скелет проекта: uv, CLI-точка входа, конфиг, health-check | ✅ | [plan](sprints/sprint-01-foundation/plan.md) · [summary](sprints/sprint-01-foundation/summary.md) |
| 02 | e2e-flow | Получение кода, план, проверка по рубрике, вывод Feedback | ✅ | [plan](sprints/sprint-02-e2e-flow/plan.md) · [summary](sprints/sprint-02-e2e-flow/summary.md) |

> **Боль, которую вскрывает этот слой:** агент проверяет все аспекты сам, читая весь код в один контекст. На реальном репо с 30+ файлами токены накапливаются быстро — к концу проверки окно раздуто, качество падает. verbose-мониторинг делает это видимым.

> **Известное ограничение (Sprint 02, fix в Sprint 04):** ~~агент может ошибочно сообщить «README отсутствует»~~ — исправлено промптами и путями `code/` в Sprint 04, валидацией в Sprint 05. ~~Раздувание оркестратора при чтении review-нот~~ — CE в Sprint 05.

### v0.2 — Изоляция: субагенты решают проблему контекста ✅

**Механизм слоя:** spawning субагентов + изоляция контекста

**Образовательная драматургия:**
- **Sprint 03** — сначала видим проблему: подключаем verbose-мониторинг контекста и запускаем v0.1-агента на объёмном репо. Пользователь наблюдает рост токенов шаг за шагом: прочитали файлы → +8K, проверили аспект А → +5K, аспект Б → +4K. К синтезу окно раздуто. Боль зафиксирована наглядно.
- **Sprint 04** — затем видим решение: вводим Reviewer-субагентов. verbose показывает контраст: субагент стартует с чистым контекстом (0 токенов истории), получает только бриф, возвращает саммари. Контекст оркестратора после делегирования вырос на 200 токенов, не на 13K.

**Ключевые результаты:**
- [x] verbose-мониторинг контекста: размер окна по шагам (sprint 03)
- [x] Наглядная демонстрация раздувания на реальном репо (sprint 03)
- [x] Spawning Reviewer-субагентов по аспектам рубрики (sprint 04)
- [x] Изолированный контекст: субагент видит только бриф + нужные файлы (sprint 04)
- [x] Саммари через файл: `workspace/notes/review-*.md` (sprint 04)
- [x] verbose-панели: запуск субагента (бриф), завершение (саммари), контекст до/после (sprint 04)

**Спринты:**
| # | Sprint | Цель | Статус | Документ |
|---|--------|------|--------|---------|
| 03 | context-bloat | verbose-мониторинг контекста; наблюдаем раздувание без субагентов | ✅ | [plan](sprints/sprint-03-context-bloat/plan.md) · [summary](sprints/sprint-03-context-bloat/summary.md) |
| 04 | subagents-isolation | Reviewer-субагенты; verbose показывает чистый контекст родителя | ✅ | [plan](sprints/sprint-04-subagents-isolation/plan.md) · [summary](sprints/sprint-04-subagents-isolation/summary.md) |

> **Боль, которую вскрывает этот слой:** субагенты изолируют аспекты, но оркестратор сам накапливает длинную историю переписки между шагами. К моменту синтеза у него 15–20K токенов истории — и это только его собственная.

### v0.3 — Context Engineering: управление окном оркестратора ✅

**Механизм слоя:** вынос в файлы + суммаризация истории + компактизация

**Цель:** устранить раздувание окна оркестратора. Агент явно выносит объёмные данные в `workspace/`, суммаризатор срабатывает при достижении порога, компактизация сворачивает историю до минимума. Каждое событие рендерится Rich-панелью: механизм, токены до/после, сэкономлено.

**Ключевые результаты:**
- [x] Вынос объёмных данных в файлы; в окне — только ссылки и саммари
- [x] Суммаризация истории по `summarization_threshold` из конфига
- [x] Компактизация при превышении `context_limit` (≥85% → overflow summarization)
- [x] verbose-панели для каждого события context engineering: механизм, до/после, экономия токенов
- [x] Валидация синтеза: фильтр ложного «README отсутствует»

**Спринты:**
| # | Sprint | Цель | Статус | Документ |
|---|--------|------|--------|---------|
| 05 | context-engineering | Механики CE + verbose-панели событий | ✅ | [plan](sprints/sprint-05-context-engineering/plan.md) · [summary](sprints/sprint-05-context-engineering/summary.md) |

> **Боль, которую вскрывает этот слой:** контекст под контролем, но рубрика одна — `default.yaml`. Все работы проверяются одинаково, независимо от темы. FastAPI-сервис и CLI-утилита получают один и тот же список вопросов.

### v0.4 — Навыки: тематические рубрики + публичные skills ✅

**Механизм слоя:** skills — переиспользуемые процедуры проверки

**Цель:** адаптировать проверку под тему задания. Рубрика описывает «что проверяем», публичный навык — «чем проверяем»: `fastapi-templates` для API, `modern-python` для качества кода. Агент уточняет тему, если она не определена.

**Ключевые результаты:**
- [x] Тематические рубрики: FastAPI-сервис, Python CLI, общий Python-проект
- [x] Подключение `fastapi-templates`, `modern-python` к соответствующим аспектам рубрики
- [x] Human-in-the-loop: уточняющий вопрос при неопределённой теме
- [x] verbose-режим: показывать, какие skills подключились и к какому аспекту

**Спринты:**
| # | Sprint | Цель | Статус | Документ |
|---|--------|------|--------|---------|
| 06 | rubrics-skills | Тематические рубрики + интеграция публичных навыков + human-in-the-loop | ✅ | [plan](sprints/sprint-06-rubrics-skills/plan.md) · [summary](sprints/sprint-06-rubrics-skills/summary.md) |

> **Боль, которую вскрывает этот слой:** всё работает, но нет финального подтверждения, что цепочка держит под нагрузкой реального, сложного проекта. Нужен E2E-тест на самом сложном доступном репо — на себе.

### v1.0 — Dogfooding: продукт проверяет сам себя ✅

**Механизм слоя:** интеграционный E2E-тест всей цепочки

**Цель:** `mentor check /path/to/ai-homework-mentor/ --verbose` возвращает осмысленный, actionable фидбэк по коду самого продукта. Все механики проходят сквозь реальную нагрузку: план → код → рубрика → субагенты с изоляцией → context engineering → синтез → фидбэк. Это финальный критерий зрелости v1.

**Ключевые результаты:**
- [x] Dogfooding-прогон без ошибок на директории проекта
- [x] Feedback содержит реальные, actionable находки по коду ментора
- [x] verbose-режим показывает все механики в работе end-to-end
- [x] README с инструкцией запуска и примерами команд

**Спринты:**
