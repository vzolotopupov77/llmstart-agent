# Пример feedback.md (dogfooding Sprint 07)

> Сгенерировано командой `mentor check . "CLI-утилита на Python" --verbose` на коде `ai-homework-mentor/`.

## Хорошо

- **Дизайн CLI:**
    - Используется `typer` для создания CLI с корневой командой `mentor` и подкомандой `check`, что обеспечивает понятную структуру.
    - Описания для корневой команды и аргументов `check` достаточно информативны.
    - Семантика exit codes в целом соблюдается (0 - успех, 1 - ошибка пользователя, 2+ - сбой).
    - Используется `rich.console.Console` для цветного вывода.
    - Наличие `Makefile` с командами `dev`, `lint`, `format`, `typecheck`, `test`, `test-backend`, `ci` является хорошей практикой. \
- **Качество кода:**
    - Соблюдается строгая типизация (аннотации аргументов и возвращаемых значений) в `code/mentor/cli.py`.
    - Хорошо реализовано разделение ответственности: `cli.py` отвечает за CLI, бизнес-логика вынесена в отдельные модули.
    - Код соответствует PEP 8, использует идиомы Python.
    - Не обнаружено мёртвого кода в `code/mentor/cli.py`.
- **Обработка ошибок:**
    - Реализован принцип fail-fast для невалидных аргументов и конфигурации.
    - Пользователь получает понятные сообщения об ошибках без traceback'ов.
    - Корректно обрабатываются timeout'ы и сетевые ошибки для внешних вызовов (OpenRouter API).
    - Не замечено "глотание" исключений (except: pass).

## Обязательно исправить

- **Тестирование:**
    - Необходимо добавить тесты для проверки вывода справки для основных команд CLI (`mentor --help`, `mentor check --help`).
    - Необходимо добавить тесты для проверки поведения CLI при передаче некорректных или отсутствующих аргументов, убедившись, что приложение корректно обрабатывает такие сценарии и выводит соответствующие сообщения об ошибках.

## Рекомендации

- **Дизайн CLI:**
    - Добавить примеры использования команд в docstring или epilog для `code/mentor/cli.py`, особенно для команды `check`. Например, `mentor check . --verbose`.
    - Рассмотреть использование `console.print(..., err=True)` для вывода ошибок в `stderr`, чтобы явно отделить их от обычного вывода. Это улучшит перенаправление потоков вывода в скриптах.
    - Уточнить, для каких ситуаций используются коды выхода `2` и `3`, чтобы пользователи могли лучше понимать природу ошибки. Это можно сделать в документации или выводе ошибки.

Это улучшит читаемость и позволит легче отлавливать ошибки на этапе статического анализа.
