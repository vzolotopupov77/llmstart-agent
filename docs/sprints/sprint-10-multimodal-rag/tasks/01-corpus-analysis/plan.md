Получить `analysis.md` — карту смысла по 66 слайдам, таксономию 5 сегментов вопросов (S1–S5) с примерами на реальных номерах слайдов, черновик датасета и ожидания/риски по методам — строго структурированный вывод (без прозы-рассуждения), как основу для датасета и метрик в Task 02.

## Роль и формат (зафиксировано пользователем)

Агент выступает как **аналитик данных для проектирования мультимодального RAG**. Источники:

- Первичный источник — 66 PNG: `data/multimodal-rag/slide-01.png … slide-66.png`.
- Вспомогательный источник (**только для анализа**, не как замена первичного) — `data/multimodal-rag/notes.md` (спикерский конспект).

Вывод — **4 секции без прозы-рассуждения**:

1. **Карта смысла по слайдам** — для каждого слайда (или группы) — где живёт смысл: в тексте / в пикселях / смешанно.
2. **Таксономия вопросов** (5 категорий, примеры + номера слайдов): S1 текст-в-тексте, S2 чтение чарта, S3 схема/расположение, S4 многослайдовый/агрегация, S5 ненаходимое (ловушка). Пороги: **≥8** вопросов на S2 и на S3, **≥4** на S1, S4, S5.
3. **Черновик датасета** — на каждый вопрос из секции 2: `id`, `segment`, `question`, `reference_answer` (из текста слайда), `gold_pages`, `required_facts`.
4. **Ожидания и риски** — по одной строке: где baseline (naive text) ослепнет; где метод B (caption) рискует выдумать число; где методы C/D (image-embed) могут просесть на русском (гипотеза MIRACL-Vision).

## Состав работ

- [ ] Прочитать все 66 PNG (`data/multimodal-rag/slide-*.png`) как первичный источник смысла.
- [ ] Прочитать `notes.md` как вспомогательный контекст (тайминг, устная подача) — не как замену визуального анализа.
- [ ] Секция 1: классифицировать каждый слайд (или логическую группу однотипных слайдов) по локализации смысла (текст / пиксели / смешанно), с кратким обоснованием на уровне слайда.
- [ ] Секция 2: сформулировать вопросы по 5 сегментам с привязкой к конкретным номерам слайдов, соблюдая пороги (≥8 S2, ≥8 S3, ≥4 S1/S4/S5 — итого ≥28 вопросов).
- [ ] Секция 3: для каждого вопроса из секции 2 заполнить `id` (`S{n}-{порядковый}`), `segment`, `question`, `reference_answer`, `gold_pages` (список id слайдов), `required_facts` (список конкретных фактов/чисел, обязательных в ответе).
- [ ] Секция 4: минимум по одной строке риска на каждый из трёх фокусов (baseline / B-caption / C-D image-embed на русском), опираясь на конкретные слайды из секций 1–2.
- [ ] Сохранить `docs/sprints/sprint-10-multimodal-rag/analysis.md` — только 4 секции, без вводного/заключительного текста.
- [ ] Самопроверка по критериям DoD ниже.

## Критерии готовности (DoD)

| # | Критерий | Способ проверки |
|---|----------|-----------------|
| 1 | Секция 1 покрывает все 66 слайдов без пропусков (поштучно или группами) | построчная сверка номеров 1–66 в `analysis.md` |
| 2 | Секция 2 содержит ≥8 вопросов S2, ≥8 S3, ≥4 S1, ≥4 S4, ≥4 S5, каждый — с номером(ами) слайда | подсчёт по секциям в `analysis.md` |
| 3 | Секция 3 — таблица/список с 6 полями (`id, segment, question, reference_answer, gold_pages, required_facts`) на каждый вопрос из секции 2, без пропущенных строк | сверка количества строк секции 3 с количеством вопросов секции 2 |
| 4 | Секция 4 содержит риски по всем трём фокусам (baseline, B, C/D-MIRACL-Vision) | наличие ≥1 строки на фокус |
| 5 | Вывод — строго 4 секции, без вступления/рассуждений/выводов сверх заданного формата | визуальная проверка структуры файла |

## Риски и допущения

- 66 изображений — объёмный vision-прогон; при необходимости разбивать на батчи по блокам презентации (см. структуру в `notes.md`: вступление 1–4, почему сейчас 5–14, дорожная карта 15–51, кейсы 52–63, финал 64–66).
- `reference_answer` строится по видимому на слайде тексту/данным, а не по устной подаче из `notes.md` — иначе датасет незаметно смещается в сторону текста, которого на самом слайде нет (это же риск, который в спринте проверяется у метода B).
- Отнесение слайда к сегменту в секции 2 частично субъективно на границах S1/S2 и S3/S4 — финальная валидация вопросов юзером на этапе примерки к реальному содержимому.
