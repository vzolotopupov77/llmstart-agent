# Corpus Analysis — Sprint 10 Multimodal RAG

## 0. СВОДКА

- **Корпус:** 66 слайдов B2B-презентации «Дорожная карта AI-first», русский язык, тёмная тема. Текст почти везде **вшит в картинку** — PDF text layer **пуст** (0/66 страниц, подтверждено Task 02).
- **Где живёт смысл:** преимущественно **визуально** — bar-chart, кривые, схемы, лестницы, айсберг, стат-боксы кейсов. Чистого «текста-в-подписи» — меньшинство слайдов.
- **Эталоны:** только с **видимого содержимого PNG**; speaker notes в eval не участвуют.
- **MIRACL-Vision / русский:** гипотеза, что визуальные эмбеддеры (C/D) на кириллице могут отставать от текстовой ветки (B) — **проверяем замером**, не вердикт.
- **Итог анализа:** 5 сегментов S1–S5; черновик §2–§3 — Task 01; **финальный eval-датасет** — `evals/datasets/multimodal/multimodal-rag/v002_2026-07-05.json` (38 items).
- **Метрики и гипотезы по методам:** [metric_map.md](./metric_map.md). Анализ ставит гипотезы; выбор метода — из чисел прогонов Task 04–08.

### 1b. Группы слайдов (сегментный взгляд)

Дополнение к построчной карте — для понимания, **где baseline ослепнет** и как распределён корпус.

| Слайды | Что на них | Сегмент / роль |
| ------ | ---------- | -------------- |
| 1, 7, 66 | титул, гэг, контакты/QR | **навигация/декор** — не источник eval-вопросов |
| 2, 6, 13–17, 22, 27, 37, 45, 46, 47, 64, 65 | тезисы, формулы, карточки, цитаты | преимущественно **S1_text** |
| 8–11, 18, 44, 49 | % в заголовке, bar-chart, кривая | **S2_chart** (число в пикселях) |
| 53–63 | кейсы: метрики в stat-боксах (−40%, ×6, 85%…) | **S2_chart**; в совокупности — материал для **S4_multi** |
| 4, 5, 12, 15, 19–21, 23–24, 28–40, 48, 50, 51, 55, 59–62 | схемы, лестницы, flow, айсберг, слои | **S3_layout** |
| 3, 41, 43 | перечни станций, тем, итогов | **S4_multi** (агрегация по слайду или блоку) |

**Распределение (грубо):** декор ~3; S1 ~12; S2 ~19 (с кейсами); S3 ~24; S4 — поверх перечисленных. Naive text baseline ослепнет на **большей части** корпуса — это ожидаемая «боль» для замера.

## 4. ОЖИДАНИЯ И РИСКИ

> Гипотезы для замеров — **не выбор метода**. Матрица метрик: [metric_map.md](./metric_map.md).

**Baseline (naive text, без notes):** PDF text layer = **0/66** → индексируются пустые passage → e5 → Qdrant. Ослепнет на S2 (8–11, 49, кейсы 53–63: числа в chart), S3 (15, 32, 38, 50: layout), S4 (Коттер на 7 слайдах). S1 частично достижим только после OCR/caption, не через PDF.

**Метод A (OCR):** поднимет S1 (заголовки/подписи), но **Layout Wall** на S2/S3 — bar-chart и схемы не становятся текстом. Риск **высокого CER** на тёмной теме и тонком шрифте (диагностика Task 04, не retrieval-скор).

**Метод B (VLM-caption):** главный кандидат на S2/S3, но риск **выдумать/перепутать число**: слайд 11 (−30–40% / −37% / 45%), слайд 10 (49/47/35/31/30%), слайд 9 (~45% vs другие % на кривой), слайд 54 (−40% нагрузки vs 7 сек). VLM **описывает**, не транскрибирует — ловим через сохранённые подписи и faithfulness.

**Методы C/D (image-embed, MIRACL-Vision на русском):** просадка на плотном кириллическом S1 (2, 8, 13); на мелких подписях схем (38, 50); на числах без крупного шрифта (18, 24). **Гипотеза:** B (текст + multilingual e5) может обогнать C на русском деке — проверяем числами.

**S4 (multi-slide):** решает **set-Recall@k** (подняли ли все `required_slides`), а не «какой метод индексации». Коттер размазан по 28–40; кейсы — по 53–63.

**S5 (unanswerable):** primary metric — **доля корректных отказов** (generation/behavior), не nDCG. Trap-slides в датасете — для retrieval-диагностики.

**Ось цены (фиксируем наравне с качеством):** `index_size_mb` · `build_time_s` · API-вызовы / ~$ · GPU. Ожидание: D (multivector) — max объём; baseline/A — min. См. отчёты Task 04–08.
