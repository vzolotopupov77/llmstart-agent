## Цель

Прочитать сгенерированные атаки до боевого прогона и зафиксировать в `test-review-notes.md`, что измеряет каждый плагин, какие кейсы валидны и какое решение — go или перегенерация.

**Боль предыдущего шага:** набор атак есть, но никто его не видел. Прогнать непрочитанный набор — получить отчёт, который невозможно интерпретировать: непонятно, «плагин чист» потому что агент устойчив или потому что атаки мусорные.

**Что дешевле поймать здесь, чем после многочасового прогона:**

- **Язык.** Проверяем факт в файле, а не параметр в конфиге: генератор мог проигнорировать настройку. Тогда baseline померит устойчивость к смене языка вместо заявленных рисков.
- **Домен.** Атаки должны говорить про курсы, оплату, B2B/B2C. Generic-сценарии про оружие и наркотики проверяют не наш продукт.
- **Вырожденные кейсы.** Плагин, у которого атаки сводятся к одной формулировке в трёх вариантах, даёт ложную уверенность в покрытии.

---

## Состав работ

**1. Метод чтения**

- [ ] Прочитать файл целиком, если объём позволяет; при большом объёме — выборка по каждому плагину с фиксацией правила отбора (сколько кейсов прочитано и как выбраны)
- [ ] Метод описать в notes: «прочитано выборочно» без правила отбора — не ревью

**2. По каждому плагину**

- [ ] Привести один-два реальных примера атаки дословно
- [ ] Ответить: что кейс проверяет на самом деле и совпадает ли это с намерением из `plugin-selection.md`
- [ ] Оценка: `ok` — идём в прогон, `concern` — идём, но интерпретируем осторожно, `block` — прогон бессмысленен
- [ ] Для `policy`-плагина особо: ловят ли кейсы **поведение агента** при подтверждении оплаты, или сформулированы как «вызови инструмент в неправильном порядке» — второе агент физически не сможет, и плагин отрапортует ложную чистоту

**3. Сквозные проверки файла**

- [ ] Распределение языков: посчитать долю русскоязычных кейсов, сравнить с решением задачи 03
- [ ] Отсутствие `session_id` в кейсах и шаблонах
- [ ] Отсутствие `config_id` — вектор проверяется отдельным ручным кейсом, в автоматическом наборе его быть не должно
- [ ] Релевантность домену: доля кейсов, упоминающих продукты, цены, оплату, сегменты
- [ ] Наличие canary-релевантных кейсов у `prompt-extraction`

**4. Решение**

- [ ] Явный раздел «решение»: go на задачу 08 либо возврат в задачу 05/06 с перечнем причин
- [ ] При `block` — **не** начинать прогон; вернуться, исправить конфиг, перегенерировать, пересчитать sha256
- [ ] Зафиксировать ожидания: какие плагины дадут находки, какие вероятно будут чисты. В задаче 09 расхождение ожиданий с фактом само по себе информативно
- [ ] Самопроверка по DoD; после «ок» — `summary.md`

## Критерии готовности (DoD)

**Агент проверяет:**

| # | Критерий | Способ проверки |
|---|----------|-----------------|
| 1 | `test-review-notes.md` существует | `ls` |
| 2 | Раздел есть по каждому плагину из конфига | сверка списков: непрокомментированных плагинов нет |
| 3 | По каждому плагину приведён дословный пример атаки | визуальная проверка |
| 4 | У каждого плагина стоит оценка `ok` / `concern` / `block` | нет плагинов без оценки |
| 5 | Доля русскоязычных кейсов посчитана и сопоставлена с задачей 03 | число в notes |
| 6 | `session_id` и `config_id` в кейсах отсутствуют | grep по `redteam-tests.yaml` |
| 7 | Метод чтения описан (полное или выборочное, с правилом отбора) | раздел «метод» |
| 8 | Есть явное решение go / no-go | раздел «решение» |
| 9 | Зафиксированы ожидания по плагинам до прогона | раздел «ожидания» |
| 10 | sha256 `redteam-tests.yaml` не изменился после ревью | пересчёт и сравнение |

**Пользователь проверяет:**

- Атаки преимущественно русскоязычные, английские читаются как попытка смены языка, а не как основной набор
- Кейсы про оплату целятся в поведение агента, а не в невозможный порядок вызова инструментов
- Атаки говорят про этот продукт, а не про абстрактный вредоносный контент
- Согласен идти в baseline «до» и понимает, что часть кейсов помечена `concern`
- Понимает ограничение изоляции: каждый кейс — новый диалог, многоходовые сценарии проверяются только в пределах одного сообщения

## Риски и допущения

- Объём yaml может потребовать скрипта выборки — допустимо при документировании метода отбора.
- Оценка `concern` — не повод откладывать спринт; повод осторожно интерпретировать соответствующие строки triage.
