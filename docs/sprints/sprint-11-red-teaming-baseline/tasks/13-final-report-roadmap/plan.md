## Цель

Превратить набор артефактов в передаваемое знание и переиспользуемый регрессионный контур, затем закрыть спринт.

**Боль предыдущего шага:** в `practice/redteam/` к этому моменту лежит около десятка файлов — threat model, конфиг, два прогона, triage, решения, сравнение. Для того, кто в спринте не участвовал, это склад. Через два месяца и для нас тоже: мы не вспомним, почему `bola` исключён из набора и почему canary живёт в рантайм-обёртке, а не в промпте.

Второй эффект, который надо закрепить: замороженный конфиг плюс набор кейсов — это **готовый регрессионный харнесс**. Если не записать, как запустить его повторно, следующий спринт начнёт с нуля и потеряет сопоставимость с этим baseline.

## Состав работ

**1. `practice/redteam/final-report.md` — шесть разделов**

- [ ] **Сводка:** находка → категория OWASP → выбранный слой → статус (`closed` / `partial` / `defer`); одна страница, детали по ссылкам
- [ ] **Индекс артефактов:** таблица «файл → что внутри → когда к нему возвращаться»
- [ ] **Антипаттерны** — из реального опыта спринта, не из общих соображений: `redteam run` вместо `eval` между прогонами, правка конфига после первого baseline, закрытие побочных эффектов промптом, guard только в JSON-пути, canary внутри версионированного промпта, публичное поле выбора конфигурации без гейта
- [ ] **Чего этот baseline не покрывает:** indirect injection через содержимое RAG, мультимодальные векторы, rate limiting и абьюз, прямой доступ к MCP-серверу, XSS на стороне виджета
- [ ] **Как повторить:** точная команда, pin версии Promptfoo, sha256 конфига и набора, требования к окружению — чтобы sprint-12 сравнивался с этим baseline, а не со своим новым
- [ ] **Метрики спринта:** число кейсов, находок, closed/partial/defer, pass rate до и после, длительность и стоимость обоих прогонов
