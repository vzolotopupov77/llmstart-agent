## Цель

Прогнать `redteam eval` против агента без защиты и сохранить сырые результаты как неизменяемую точку отсчёта вместе со всем окружением прогона.

**Боль предыдущего шага:** после задачи 07 всё готово, но состояние агента нигде не зафиксировано. Без baseline «до» разговор о результате фиксов вырождается в «кажется, стало лучше».

**Главная опасность шага — неполнота фиксации.** Через месяц отчёт без контекста бесполезен: неизвестна версия Promptfoo, промпт, состояние реранкера, отвечал ли Neo4j. Если что-то из этого изменится к задаче 12, разница в отчётах будет объясняться окружением, а не фиксами — и мы этого не заметим.

**Вторая опасность — ложно-зелёный прогон.** Если backend упал на середине или таргет отвечал ошибками, Promptfoo честно отрапортует, что атаки не сработали. Отсутствие находок надо уметь отличить от отсутствия ответов.

> 💡 **Skills:** `promptfoo-redteam-run` — форма команды `eval` с готовым набором кейсов, куда пишутся результаты, как получить отчёт.

## Состав работ

**1. Предусловия и фиксация окружения**

- [ ] Проверить решение `go` в `test-review-notes.md`
- [ ] Сверить sha256 `promptfooconfig.yaml` и `redteam-tests.yaml` со значениями задач 05 и 06
- [ ] Убедиться, что `SECURITY_ENABLED` отсутствует или `false`; зафиксировать фактическое значение
- [ ] Поднять стек: backend `:8003`, `mcp_server`, Qdrant, Neo4j; проверить `/health` и `/ready`
- [ ] Записать в манифест: версия Promptfoo, версия Node, commit репозитория, `OPENAI_MODEL`, имя промпта по умолчанию (V1), `RETRIEVER_BACKEND`, `RERANKER_ENABLED`, значение canary, дата и время старта

**2. Прогон**

- [ ] `practice/redteam/node_modules/.bin/promptfoo redteam eval` с замороженным конфигом и набором из `redteam-tests.yaml`
- [ ] Команда `redteam run` **запрещена** — она перегенерирует кейсы
- [ ] Полный stdout и stderr писать в файл сразу, а не собирать из терминала после
- [ ] Зафиксировать exit code, длительность, оценку стоимости в OpenRouter

**3. Сохранение результатов**

- [ ] В `practice/redteam/baseline-before/`: `eval-log.txt`, машиночитаемый отчёт (json), человекочитаемый отчёт, `run-manifest.md`
- [ ] Проверить целостность: число исполненных кейсов = число кейсов в `redteam-tests.yaml`
- [ ] Пометить директорию как неизменяемую: дальше только чтение

**4. Санитарная проверка «прогон был настоящим»**

- [ ] Убедиться, что в результатах есть непустые ответы агента, а не сплошные ошибки транспорта
- [ ] Посчитать долю кейсов с ошибкой запроса; при заметной доле — разобраться, отказ агента это или падение стека
- [ ] Проверить, что хотя бы в части кейсов агент вызывал инструменты
- [ ] Самопроверка по DoD; после «ок» — `summary.md`

## Критерии готовности (DoD)

**Агент проверяет:**

| # | Критерий | Способ проверки |
|---|----------|-----------------|
| 1 | `baseline-before/` содержит лог, json-отчёт, человекочитаемый отчёт, манифест | `ls` |
| 2 | Использована команда `redteam eval` | grep по логу: `redteam run` отсутствует |
| 3 | sha256 конфига и кейсов совпадают со значениями задач 05 и 06 | сравнение |
| 4 | Фактическое значение `SECURITY_ENABLED` зафиксировано | grep по манифесту |
| 5 | Манифест содержит версии Promptfoo, Node, commit, модель, имя промпта, параметры retrieval | сверка по списку |
| 6 | Число исполненных кейсов = число кейсов в наборе | сравнение чисел |
| 7 | Exit code, длительность, оценка стоимости зафиксированы | запись в манифесте |
| 8 | Доля кейсов с транспортными ошибками посчитана | число в манифесте |
| 9 | В результатах есть непустые ответы агента и вызовы инструментов | выборочная проверка отчёта |

**Пользователь проверяет:**

- Принимает, что часть кейсов «пройдёт» с уязвимостью — для baseline «до» это ожидаемо
- Убедился по манифесту, что зафиксировано достаточно для повтора прогона через месяц
- Убедился, что прогон был настоящим: ответы непустые, инструменты вызывались
- Согласен, что `baseline-before/` дальше не редактируется

## Риски и допущения

- Долгий прогон допустим; урезать набор кейсов между прогонами нельзя.
- Локальный агент может упасть mid-run — перезапуск допустим только при неизменных конфиге и наборе кейсов, с пометкой в манифесте.
- Стоимость прогона фиксируется, чтобы задача 13 могла посчитать цену baseline.
