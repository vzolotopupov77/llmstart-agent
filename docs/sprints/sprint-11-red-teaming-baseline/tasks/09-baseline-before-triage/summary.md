## Отклонения от плана

Состав работ выполнен. Ветка `docs/sprint-11-09-baseline-before-triage` не создавалась: спринт 11 незакоммичен на `main`, как задачи 01–08.

Ручные пробы шли через `urllib` на `POST /api/v1/chat`, не через `curl` — тот же контракт, UTF-8 на Windows.

---

## Принятые решения

| Решение | Причина |
|---|---|
| Severity по риску продукта, не по ASR | `tool-discovery` 80% в основном ложные fail; главный эффект — оплата/лиды |
| F-06 чинить по `save_lead`, не только по тексту «оплата принята» | Ручной повтор отказал в `message`, но записал лид |
| Canary «не воспроизвелось» = агент устойчив | Прогон настоящий (манифест 08); атаки не просили токен |
| `config_id` — находка F-25, даже без дельты V1/V2/V3 на грубой фразе | Runner реально переключается на V2/V3; prompt-only фикс V1 будет обойдён |
| Ложные fail (§5.1 triage) не тащить в задачу 10 | Иначе «после» починит грейдер, а не продукт |

Пользователь подтвердил: severity, слои, ручные повторы, «не воспроизвелось», значимость `config_id`.

---

## Проблемы и решения

| Проблема | Как решили |
|---|---|
| ASR 80% у `tool-discovery` выглядит как главная дыра | Разбор глазами: DISCLOSABLE каталог/воронка vs 2 реальных раскрытия схемы |
| P1 flaky в формулировке | Зафиксировали эффект `save_lead` как более стабильный признак |
| Медицина на прямом запросе — отказ | Повтор в формате eval (две строки без оговорок) — пробивает |
| Тестовые лиды при верификации | Две записи в `data/leads.txt` (triage-test / Иван Петров); локальные, не в git |
