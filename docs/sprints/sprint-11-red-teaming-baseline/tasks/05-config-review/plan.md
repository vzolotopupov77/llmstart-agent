## Цель

Пройти чек-лист по сгенерированному конфигу, руками исправить расхождения и заморозить конфигурацию зафиксированной контрольной суммой.

**Боль предыдущего шага:** генератор выдаёт правдоподобный yaml — и именно поэтому опасен. Типовые дефекты: URL из примеров документации, `search_knowledge_base` из устаревшего `architecture.md`, «улучшенный» набор плагинов относительно задачи 03, `stateful: true` при отсутствии `session_id`.

**Самый дорогой дефект — молчаливый:** если `transformResponse` извлекает не то поле, грейдер получает пустую строку и **все проверки проходят**. Отчёт зелёный, прогон бессмысленный. Поймать это можно только пробным вызовом, поэтому dry-run — обязательная часть ревью, а не опция.

## Критерии готовности (DoD)

**Агент проверяет:**

| # | Критерий | Способ проверки |
|---|----------|-----------------|
| 1 | Чек-лист заполнен, все 12 пунктов в состоянии `pass` | `config-review-checklist.md` |
| 2 | Конфиг проходит валидацию после правок | команда validate |
| 3 | Dry-run вернул непустой извлечённый ответ агента | фрагмент вывода в чек-листе |
| 4 | Расхождений между yaml и `plugin-selection.md` нет | сравнение списков плагинов и стратегий |
| 5 | sha256 конфига зафиксирован | запись в чек-листе |
| 6 | Конфиг не перегенерировался — только точечные правки | `git diff` показывает локальные изменения, не переписанный файл |

**Пользователь проверяет:**

- Прочитал `config-explainer.md` и согласен, что конфиг проверяет то, что заявлено в модели угроз
- Убедился по выводу dry-run, что грейдер получает текст ответа агента, а не пустоту
- Согласен заморозить конфиг: дальше меняется только код фиксов и флаг
- Если правок было много — согласен с замечаниями, внесёнными в промпт генерации

## Риски и допущения
