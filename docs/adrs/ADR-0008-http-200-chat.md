# ADR-0008 — HTTP 200 для всех ответов /chat, ошибки в теле

> **Статус:** ✅ Accepted  
> **Дата:** 2026-06-05  
> **Область:** API-контракт, обработка ошибок  
> **Supersedes:** —

---

## Контекст

`POST /chat` — долгий запрос; в SSE-режиме HTTP-статус отправляется до начала стриминга. Если агент падает в середине потока, HTTP 500 уже не отправить. Нужно согласованное поведение между JSON и SSE режимами.

## Решение

`POST /chat` **всегда возвращает HTTP 200**. Бизнес-ошибки (LLM недоступен, превышен лимит) передаются как событие `error` в SSE-потоке или как поле `error` в JSON-ответе.

Исключения: `422` (невалидный запрос — до запуска агента), `503` (сервис полностью недоступен).

## Последствия

- `+` Единообразное поведение JSON и SSE: клиент всегда проверяет тело, а не только статус.
- `+` SSE-клиент может показать пользователю текст ошибки вместо обрыва соединения.
- `−` Нестандартно: HTTP-статус 200 при логической ошибке требует явного документирования.
