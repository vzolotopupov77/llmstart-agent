# ADR-0006 — Один /chat endpoint, JSON vs SSE через Accept header

> **Статус:** ✅ Accepted  
> **Дата:** 2026-06-05  
> **Область:** API-контракт  
> **Supersedes:** —

---

## Контекст

Core должен отвечать и JSON (Telegram, тесты) и SSE-потоком (веб-виджет). Варианты: два endpoint'а (`/chat` и `/chat/stream`) или один с переключением через заголовок.

## Решение

Один endpoint **`POST /chat`**. Режим выбирается через `Accept`:
- `application/json` → единый JSON-ответ после завершения агента.
- `text/event-stream` → SSE-поток событий (`reasoning`, `tool`, `done` и др.).

## Последствия

- `+` Единый контракт — меньше дублирования логики маршрутизации.
- `+` Telegram-бот и тесты используют JSON без изменений.
- `−` Нестандартное использование `Accept` для разграничения режимов — требует документирования.
